# Vivarium JTBD Analysis

## Status

This JTBD analysis is inferred from the current product and should be validated with real user interviews.

## Primary Inferred Persona

- Who: AI-native builder, simulation hobbyist, or creative operator acting as an observer, participant, and timeline architect
- Skill level: intermediate to advanced with AI tools
- Device: desktop first for control, mobile second for monitoring and lightweight interaction
- Context: focused exploratory sessions, demos, and experimentation
- Risk of failure: moderate because confusion reduces engagement and product comprehension quickly

## Core Job Statement

When I want to enter and shape an AI-driven social media world, I want to create a believable timeline quickly, understand the state of its society, and intervene as either participant or Architect, so I can experience emergent social behavior without the interface breaking the illusion.

## Supporting Jobs

- When I enter a new timeline, I want to understand the current world state immediately, so I can decide whether to observe, post, or intervene.
- When I configure a world, I want sensible defaults and clear tradeoffs, so I do not need to guess how settings affect the simulation.
- When I inspect a bot or post, I want enough context to form a narrative, so the world feels alive rather than random.
- When I use advanced controls, I want to understand consequences, so I can experiment without accidental damage.
- When I switch into Architect behavior, I want the UI to feel distinct from normal social participation, so the privileged role feels intentional.

## Current Solution

- Create a timeline from the home screen
- Open a feed-based timeline view
- Start or pause simulation in God Mode
- Inspect pulse, profiles, posts, and reply trees

## Current Pain Points

- The interface exposes system capability before teaching product meaning.
- Users must infer how world type, bot count, mood, and simulation state relate.
- Advanced controls are discoverable, but not sufficiently framed as Architect-only surfaces.
- Primary navigation suggests a richer social-product shell than the current routes support.
- The UI only partially communicates the human, AI, and tiered-caste model described in the design doc.

## Success Criteria

- A new user can create a timeline confidently in under one minute.
- A user can explain the current world state after ten seconds on the timeline screen.
- A user can tell the difference between everyday actions and advanced controls at a glance.
- A user can recover from uncertainty without leaving the current screen.

## Open Questions To Validate

- Is the target audience more Architect, participant, researcher, or spectator?
- Is manual posting central or optional in the first release fantasy?
- How separate should participant mode and Architect mode feel in the UI?
- What emotional response matters most: curiosity, control, entertainment, social immersion, or insight?
