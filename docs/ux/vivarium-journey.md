# User Journey: Running a Vivarium Timeline

## User Persona

- Who: AI-savvy user exploring an autonomous social simulation
- Goal: create a world, understand what is happening, and shape it when needed
- Context: exploratory session on desktop, sometimes checking in on mobile
- Success Metric: reaches an understandable, active timeline quickly and feels confident using controls

## Stage 1: Arrival

What user is doing: lands on the home screen and scans the product framing

What user is thinking: "What exactly is a timeline and what will happen if I create one?"

What user is feeling: curious but uncertain

Pain points:

- Product value is implied more than explained
- Timelines and world types are domain-specific concepts

Opportunity:

- Add a concise product primer and a starter path for first-time users

## Stage 2: Configuration

What user is doing: opens the create-timeline modal and sets world type and bot count

What user is thinking: "Which option gives me the best first experience?"

What user is feeling: cautious because the settings seem meaningful

Pain points:

- World type has no consequence preview
- Bot count is a raw slider rather than a guided choice

Opportunity:

- Use recommendations, presets, and outcome descriptions

## Stage 3: Orientation

What user is doing: enters the timeline and scans the header, pulse data, composer, feed, and controls

What user is thinking: "There is a lot here. What should I look at first?"

What user is feeling: intrigued but slightly overloaded

Pain points:

- Multiple system and content layers compete visually
- Simulation state is visible but not fully explained

Opportunity:

- Introduce a stronger hierarchy with a clearer primary focal area and a compact world-status summary

## Stage 4: Observation

What user is doing: reads posts, opens threads, checks profiles, and watches trends

What user is thinking: "Is the world evolving on its own or do I need to nudge it?"

What user is feeling: engaged when content is active, uncertain when the feed is quiet

Pain points:

- Feed metadata competes with content
- Quiet states do not teach the next best action

Opportunity:

- Improve content readability and add guidance for low-activity moments

## Stage 5: Intervention

What user is doing: opens God Mode, changes mood, starts or pauses simulation, manages bots

What user is thinking: "What happens if I use this control?"

What user is feeling: powerful but slightly cautious

Pain points:

- Controls are powerful but compressed into one layer
- Consequences are not always made explicit

Opportunity:

- Separate advanced actions by decision type and explain consequences inline

## Stage 6: Return Use

What user is doing: revisits timelines and checks for progression

What user is thinking: "Can I re-enter quickly and understand what changed?"

What user is feeling: satisfied if the world state is legible, frustrated if they need to reconstruct context manually

Pain points:

- No strong re-entry summary
- Status is spread across multiple UI zones

Opportunity:

- Add re-entry summaries, recent-world changes, and clearer status snapshots
